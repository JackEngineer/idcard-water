# 本地证件水印工具首版设计

日期为 2026-11-13。

用户已于 2026-11-13 确认本设计，采用 Tauri 2 并允许界面使用网页技术。本文为首版产品范围和交互规则的实施依据，不代表应用已经实现或通过验证。

## 产品目标

用户在发送身份证照片之前，在本机添加用途水印。macOS 和 Windows 用户不需要命令行，也不需要账号或远程服务。

首版围绕导入图片、填写水印、预览和另存四个动作设计。水印直接合成到输出图片的像素中。原图保持不变。

水印用于声明用途并增加滥用成本，不保证无法去除，不提供法律效力保证，也不阻止接收方转发。

## 首版范围

| 项目 | 设计约定 |
| --- | --- |
| 平台 | macOS 的 Apple Silicon 与 Intel 机型，以及 Windows x64。发布时只列出实际完成安装验收的系统版本。 |
| 界面 | 中文单窗口桌面应用。首版不增加账户、路由、多窗口或后台常驻功能。 |
| 导入 | 文件选择与拖入均支持。一个会话最多容纳两张图片，满足身份证正反面的使用场景。 |
| 输入格式 | 支持静态 JPEG 和 PNG，以文件内容识别格式。HEIC、PDF 和多帧图片不纳入首版，遇到时明确提示。 |
| 水印 | 多行中文文本、重复铺设、透明度、字号、颜色和角度。两张图片共用一份水印配置。 |
| 预览 | 查看两张图片各自的水印结果，支持适应窗口和放大检查。 |
| 导出 | JPEG 或 PNG。可以导出当前图片，也可以将两张图片分别导出到同一目录。默认 JPEG。 |
| 保存 | 不覆盖原图，不自动覆盖已有文件，不保存编辑历史或最近文件。 |

首版不包含裁剪、遮挡号码、正反拼图、OCR、PDF、云同步、隐形水印、剪贴板输出和应用内自动更新。上述功能不作为首版验收前提。

HEIC 是手机照片兼容性的重要限制。界面和发行说明必须披露该限制，不把 AVIF 支持当成 HEIC 支持，也不静默调用外部转换服务。

## 使用流程

打开应用时显示导入入口，以及“图片仅在本机处理”的说明。说明旁可以展开查看具体隐私规则。

用户选择或拖入图片后，Rust 端读取输入并生成会话。界面显示图片缩略图与预览，不显示或记住完整文件路径。用户可以移除单张图片。已有两张图片时，再次导入须先移除图片，不能静默替换。

水印内容初始为空。输入框以示例提示用户填写接收方和用途，但示例不作为实际水印文本。提供“插入今天日期”动作，插入本机日期，而不是每次渲染时自动改变日期。

推荐示例为“仅供某某公司办理入职手续使用”，下一行填写日期。应用不要求用户输入身份证号，也不读取图片中的证件文字。

用户调整样式时，界面标明预览正在更新。预览只显示当前水印版本的结果。较早请求完成后不得覆盖较新的结果。

导出入口显示图片数量和输出格式。导出使用一次固定的配置快照。导出期间暂时禁用图片替换、参数编辑和重复导出，避免用户误判正在输出的内容。

完成后逐张展示成功或失败。某张图片失败时，不删除另一张已经成功导出的图片，也不声称整批已经成功。失败项重试沿用该批次的配置快照。用户修改参数后再次导出时视为新批次，不复用旧批次的成功状态。

## 水印和图像规则

水印默认斜向重复铺设。初始透明度为 24%，初始角度为负 30 度，字号以图像短边的 3.5% 计算。上述值是待用户预览确认的设计默认值，不是已验证的最佳效果。

字号和间距依据原图尺寸计算，而不是依据窗口像素计算。因此，两张不同尺寸的图片可以使用相同配置。首版不提供手动拖动单条水印的位置。

文本必须包含非空白字符。首版最多接受 200 个 Unicode 标量值和 4 行用户输入。过长时给出明确提示，不静默截断。排版允许自动换行，仍不能完整放入图像时阻止导出，并提示缩短内容或调整字号。

至少有一组完整水印位于图内，其他重复水印可以在图像边缘裁切。应用不允许只显示少量边角水印却把该结果当作正常默认效果。

Rust 端先应用输入图片的方向信息，再计算水印位置。预览与导出使用同一个排版和合成实现。预览是合成结果的缩小版本，不由 HTML 或 Canvas 再画一套水印。

导出不主动改变图像的显示尺寸。JPEG 编码质量默认 95，PNG 保持无损编码。JPEG 的重新编码可能损失细节，不能宣传为无损导出。

PNG 的透明区域在合成前以白色背景铺底，预览与两种导出格式使用相同结果。这样可以避免接收方切换背景后看不到文字，也避免 JPEG 与 PNG 的预览背景不一致。

输入颜色应归一化到标准 sRGB。带 ICC 配置的样本必须包含在验收中。无法正确转换的输入应明确报错，不能静默忽略配置并声称颜色一致。

## 技术选型

| 层 | 首版默认选择 | 职责 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 窗口、原生文件选择、拖入登记、保存位置选择和打包。 |
| 界面 | React、TypeScript、Vite | 表单、图片切换、预览展示、任务状态和错误提示。 |
| 图像核心 | 独立 Rust 模块 | 解码、方向与颜色归一化、中文排版、水印合成和编码。 |
| 图片基础库 | image | JPEG、PNG 的解码与编码。实际依赖版本在实施时锁定。 |
| 字体 | 随包携带的 Noto Sans CJK SC | 水印文字渲染，不依赖远程字体或用户电脑的字体安装情况。保留字体版权与许可证。 |
| 状态管理 | React 内置状态能力 | 首版不增加独立状态库。 |
| 持久化 | 无用户数据存储 | 首版不引入数据库。静态配置和字体随安装包提供。 |

图片核心不依赖 React 或 Tauri。桌面适配层只处理原生操作、任务调度和输入输出授权，不实现另一套水印规则。

应用不启动对外 HTTP 服务。界面仅加载随包提供的静态资源。不嵌入远程网站，不下载脚本和字体。

## 数据和状态边界

采用以下领域概念组织状态，避免用互相矛盾的忙碌、完成和失败标记组合表示任务。

| 概念 | 内容与不变条件 |
| --- | --- |
| 图片会话 | 会话标识、显示名和导入时读取的输入字节快照。每个会话对应一张输入图片。原始文件路径只留在 Rust 端用于授权与防覆盖判断。 |
| 水印配置 | 文本、颜色、透明度、角度和相对字号。经过 Rust 边界校验后才进入排版与合成。 |
| 预览版本 | 图片会话标识与配置版本。界面只接纳当前版本的预览。 |
| 导出请求 | 固定的图片集合、水印配置快照、输出格式与已授权的目标目录。不能依赖稍后可能改变的界面状态。 |
| 导出结果 | 每张图片的成功结果或可操作错误。批量部分成功不是全部失败，也不是全部成功。 |

应用的主要状态为等待导入、正在导入、可编辑、正在导出。错误附着在对应操作上，失败后回到仍有有效输入的可编辑状态，或回到等待导入状态。

没有有效图片或水印文本时，导出不可用。预览失败时也不能提供一个会绕过水印处理的“直接导出”备用路径。

原图字节和未加水印的原尺寸像素不发送给界面。界面接收派生缩略图、预览字节与状态。水印文本为空时，可以显示未加水印的缩略图用于确认输入，但不能导出。文本有效后显示带水印预览。放大检查时请求足够分辨率的合成预览，不能只放大低分辨率缩略图。预览通过限定用途的 IPC 返回，不开放任意文件浏览或文件读取接口。

文件选择和拖入应由原生层登记用户授权的输入。Rust 端验证实际文件类型、输入数量、尺寸和资源上限。不能仅依赖前端检查或文件扩展名。

首版输入上限为每张 50 MiB 和 6400 万像素。超限时先提示，不继续尝试大规模分配。原尺寸解码和合成串行执行，避免两张大图同时争抢内存。发布前用上限内样本验证资源占用，不把这些输入限制误写为进程内存占用保证。

## 导出和隐私边界

应用不主动外联，不包含统计、图片上传、云端错误上报和自动更新模块。系统自身的网络活动不属于这一承诺，但应用不得借用系统服务上传图片。

除用户主动导出外，不把输入字节、预览或水印文本写入应用数据目录、日志、临时目录或崩溃报告服务。输入文件本身已经存在于用户磁盘，不在此规则之外创建副本。

导出从合成后的像素重新编码。不复制源图 EXIF、GPS、XMP、注释或内嵌缩略图。方向已应用到像素，不再依赖源图方向字段。需要的标准颜色标记只能使用应用生成的 sRGB 信息，不复制源图中的任意附加字段。

候选文件名为原文件名去掉扩展名后追加 `_watermarked` 和新扩展名。若文件名已经存在，追加编号，且在实际写入时仍禁止覆盖，不能只在写入前检查一次。

导出路径必须与所有输入文件的真实路径区分，拒绝覆盖输入文件。目标文件若是已有链接或其他已存在对象，同样不能覆盖。失败不得修改原图。

必要的临时文件只允许位于用户选定的导出目录，且只保存已经加水印的编码结果。成功后提交到目标文件名，失败或取消时尽力清理临时文件。应用不承诺断电情况下绝无残留，也不承诺磁盘安全擦除。

显示错误时使用文件显示名和可操作说明，不把完整路径、图片内容或水印文本写入诊断日志。存储介质、备份、交换空间和系统崩溃转储不受应用完全控制，隐私说明必须如实写明。

退出或移除图片时释放对应会话和预览。导出的图片由用户自己保管，应用无法阻止云盘同步、系统截图或接收方再次传播。

## 错误处理

| 情况 | 用户看到的行为 |
| --- | --- |
| 不支持的格式或多帧图片 | 显示支持范围，不生成不完整结果。 |
| 图片损坏、超出资源上限 | 明确报错，不崩溃，不继续分配超限资源。 |
| 文本为空、超长或无法完整排版 | 指出需要修改的参数，不允许导出无水印图片。 |
| 中文字符不在字体覆盖范围 | 提示存在无法渲染的字符，不用缺字方框静默替代。 |
| 文件无权限、磁盘空间不足、设备移除 | 保留当前编辑会话，允许用户更换导出目录后重试。 |
| 用户取消选择目录 | 回到可编辑状态，不提示导出成功，也不创建输出文件。 |
| 两张图片中只有一张导出成功 | 分别显示结果，只对失败图片提供重试入口。 |

## 验收依据

全部测试图片使用虚构信息，不将真实身份证、接收方数据或实际用途文本提交到公开仓库或 CI。

图像核心的验证必须覆盖中文、多行、长文本、不同分辨率、横竖方向与镜像方向、透明 PNG、带 ICC 的图片、损坏图片和资源超限输入。

预览验证应比较同一配置下的合成结果。导出验证应重新打开实际输出文件，检查文字覆盖、方向、尺寸和清晰度，不能只证明编码函数返回成功。

隐私验证应构造包含 GPS、XMP 和内嵌缩略图的输入，并用独立元数据检查工具确认输出没有复制这些字段。还应检查应用数据目录和诊断记录是否出现敏感副本。

文件安全验证应覆盖文件重名、目标是链接、输入与输出位置冲突、写入失败、取消操作和部分成功。操作前后比较原图内容，确认未发生改变。

真实桌面验收应在 macOS 与 Windows 上使用安装包完成导入、修改、放大预览和导出。还应验证过期预览不能覆盖新预览，重复点击不能启动重复导出，大图处理时窗口仍能响应操作。

离线验收应在断网环境中完成首次安装、首次启动和整个处理流程。联网观察只能作为应用没有主动外联的证据之一，不能仅凭一次抓包就宣称永远不存在数据泄漏。

## 交付顺序

先验证桌面运行条件、中文水印、方向处理、颜色转换和大图资源占用。验证产物使用合成图片。未验证前，不承诺最低系统版本、速度或内存指标。

然后实现并测试独立 Rust 图片核心。核心的输出正确、源图安全和元数据规则应先于界面接线成立。

随后连接单窗口界面，完成导入、配置、预览、两张图片切换和导出。界面验收时展示实际运行截图，用户确认交互后再进入发行验收。

最后在各目标系统上打包、安装并完成离线验收。Windows 的首次离线安装应使用包含 WebView2 运行时安装程序的方案，不能依赖联网下载引导器。macOS 对外分发纳入 Developer ID 签名和 Apple 公证。Windows 同时评估代码签名，不能把没有 SmartScreen 提示作为未经验证的承诺。

缺少 Windows 验证环境、签名身份或发行凭据时，应如实记录发行阻碍。能构建不等于已经具备可发布安装包。

本设计确认后，再编写逐项实现计划。当前不自动创建应用代码、提交、推送、发布或合并。

## 设计取舍

Experience First 原则将首版收敛为一个完整的证件水印流程，排除通用修图和账户功能。

Boundary Discipline 原则将文件授权、校验和错误呈现放在应用边界，将图像规则集中在独立 Rust 核心。

Model the Domain 原则用图片会话、配置版本和导出快照区分状态，避免导出期间读取到变化中的参数。

Sequence work into verifiable units 原则使图像核心、桌面交互和安装包分别接受验收。Prove It Works 原则要求检查真实输出文件和真实安装包，而不是仅检查编译成功。
